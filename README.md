# Snowfall

Лёгкий оверлей со снегопадом для рабочего стола Windows. Прозрачное окно
поверх экрана, пропускающее клики; снег идёт на заднем плане, ложится
сугробами на верхние края окон, панель задач и низ экрана, а при закрытии
или сворачивании окна осыпается вниз.

## Требования

- Windows 10 1903+ (DirectComposition, DX12)
- Rust stable, `cargo`

## Сборка и запуск

```
cargo build --release
target\release\snowfall.exe
```

Выход: **Ctrl+Alt+Shift+Q**. Интерфейса и значка в трее нет.

## Структура

```
snowfall/
├─ src/main.rs          точка входа
├─ core/                не зависит от ОС: симуляция и рендер (wgpu)
│  └─ src/
│     ├─ lib.rs         фасад Snowfall: new / set_windows / reset / tick
│     ├─ gpu.rs         адаптер, устройство, конфигурация surface
│     ├─ sim.rs         буферы и compute-пайплайны
│     ├─ render.rs      render-пайплайны, stencil-вырезание окон
│     ├─ surfaces.rs    верхние края окон, слоты поверхностей
│     ├─ common.wgsl    общие структуры (Params, Particle, Surface)
│     ├─ sim.wgsl       compute-ядра
│     └─ render.wgsl    вершинные и фрагментные шейдеры
└─ windows/             только Windows: окно, список окон, главный цикл
   └─ src/
      ├─ overlay.rs     WS_EX_TOPMOST | LAYERED | TRANSPARENT | NOACTIVATE,
      │                 визуал DirectComposition, горячая клавиша выхода
      ├─ desktop.rs     перебор окон (DWM-границы), детект полноэкранного режима
      └─ lib.rs         цикл: опрос окон, пауза/возобновление, tick
```

`core` принимает от платформенного слоя `wgpu::Surface` и список
прямоугольников окон в порядке z-order (`Rect`). Поддержка Linux сводится к
новому крейту рядом с `windows/`, который создаёт surface и отдаёт список окон.

## Как это работает

### Кадр

1. `Sim::encode` записывает пять compute-запусков: `update_particles`,
   `pop_deposits`, `advance_head`, `settle_even`, `settle_odd`.
2. `Draw::encode` рисует: вырезание окон (stencil) → сугробы → частицы.
3. Один `submit` и `present` (Fifo / vsync). Темп кадров задаёт `Present`,
   таймеры Windows не используются, поэтому кадры идут ровно.

С CPU за кадр уходит только `Params` (48 байт).

### Частицы

Один буфер на снежинки (700) и осыпающийся снег (4096), запись 32 байта:

| поле | назначение |
|---|---|
| `pos`, `radius`, `alpha` | читаются вершинным шейдером как один `vec4` |
| `vel` | снежинка: (фаза, качание); осыпь: скорость |
| `amount` | осыпь: масса снега |
| `delay` | осыпь: задержка перед отрывом |

Снежинки: ветер + качание + падение, респаун сверху. Осыпь: гравитация,
сопротивление воздуха, предельная скорость. `radius == 0` — мёртвая частица
(вырожденный квад, ничего не рисует).

### Сугробы

На каждую поверхность (верх окна, панель задач, низ экрана) выделен слот.
Высота хранится в узлах через `BIN = 4` px на глобальной сетке x, формат
фиксированной точкой в `atomic<i32>` (`FX = 4096`).

- **Накопление.** Приземлившаяся частица добавляет снег в случайный соседний
  узел атомарным `atomicAdd` (веса 0.5 / 0.25 / 0.25, случайный размер).
- **Осыпание по склону.** `settle_even` / `settle_odd` обрабатывают чётные и
  нечётные пары узлов, так что каждая пара принадлежит одному потоку. У пары
  свой стабильный предел крутизны (`SLOPE` × 0.4…1.6), поэтому профиль
  остаётся неровным.
- **FIFO-удаление.** Каждое приземление пишется в журнал `deposits`
  (кольцевой буфер на 8192 записи: узел, масса, момент истечения =
  `clock + SNOW_LIFE`). `pop_deposits` берёт записи с головы журнала;
  у кого срок вышел, у того ровно эта масса снимается с узла
  (`atomicAdd` с возвратом излишка, не ниже нуля; если склон уже унёс часть
  снега — добирает с соседних узлов). `advance_head` сдвигает голову. Записи упорядочены по
  времени, поэтому истёкшие всегда образуют префикс. Анимации нет: самый
  старый снег просто исчезает. Высота узла = сумма осадков за последние
  `SNOW_LIFE` секунд, то есть случайная величина, а не ровное плато. При
  переполнении журнала (запас `OVERFLOW_MARGIN`) старые записи истекают
  досрочно. `MAX_H` — страховка.
- **Рендер.** Вершинный шейдер читает буфер высот напрямую (vertex pulling),
  один квад на пару соседних узлов; верхний край растворяется на ~2.5 px.

### Слоты и осыпание

`Slots` (CPU) сопоставляет новые края окон со слотами: тот же слот, если
совпала высота (±1.5 px) и хотя бы одна боковая граница (±2 px). Сдвиг окна
целиком считается новой поверхностью.

Исчезнувшая поверхность получает состояние `RELEASING`; ядро `release_snow`
превращает снег её узлов в частицы (до 4 на узел, кольцевой буфер через
атомарный счётчик, старые перезаписываются) со случайной задержкой до 0.5 с.
Частицы падают и приземляются на ближайшую активную поверхность ниже. То же
происходит с узлами, выпавшими из-под перекрытия другим окном.

### Снег «за окнами»

Оверлей находится поверх всех окон. Прямоугольники окон (по
`DWMWA_EXTENDED_FRAME_BOUNDS`) рисуются первым проходом только в stencil
(`Stencil8`), сугробы и частицы проходят тест `stencil == 0`. Стоимость не
зависит от числа окон на пиксель.

### Пауза

Раз в 200 мс опрашивается активное окно. Если оно развёрнуто или перекрывает
монитор целиком, оверлей скрывается, рендер и compute прекращаются (опрос
дальше раз в 500 мс, `EmptyWorkingSet`). При выходе из такого режима
вызывается `reset()`: снегопад начинается сверху, сугробы очищены.

## Настройка

Константы в начале шейдеров.

| файл | константа | что меняет |
|---|---|---|
| `sim.wgsl` | `FLAKE_ALPHA`, `FLAKE_ALPHA_VAR` | прозрачность снежинок |
| `sim.wgsl` | `AMOUNT_PER_AREA` | сколько снега даёт снежинка |
| `sim.wgsl` | `SLOPE` | крутизна сугробов |
| `sim.wgsl` | `SNOW_LIFE` | через сколько секунд снег убирается (FIFO) |
| `sim.wgsl` | `GRAVITY`, `DEBRIS_AMOUNT`, `MAX_CHUNKS` | осыпание |
| `render.wgsl` | `PILE_ALPHA` | прозрачность сугробов |
| `common.wgsl` | `MAX_H` | предельная высота сугроба |
| `sim.rs` | `FLAKES`, `DEBRIS`, `DEPOSITS`, `POP_BATCH`, `MAX_SLOTS`, `BIN` | размеры пулов, журнала и сетки |

Размер снежинок и скорость падения задаются в `spawn_flake` / `update_flake`.

## Ограничения

- Только основной монитор.
- Снег хранится для 63 поверхностей плюс низ экрана; `DEBRIS` — размер пула
  осыпи, при массовом закрытии окон старые частицы пропадают.
- Всплывающие меню и окна без заголовка не попадают в список окон:
  снег может идти поверх них. Скруглённые углы окон вырезаются как углы
  прямоугольника.
- Память: `wgpu` + DX12 занимают десятки мегабайт, поэтому заявленные ~8 МБ RAM
  недостижимы; ожидайте порядка 25–40 МБ. Буферы симуляции — около 0.4 МБ.
- На мониторах с высокой частотой кадр рисуется на каждый vsync, нагрузка
  растёт пропорционально частоте.
